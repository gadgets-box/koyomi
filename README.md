# 今日の暦 — 日めくりカレンダー

旧暦・六曜・二十四節気・今日は何の日・生まれてから何日目、を1枚の「日めくりカレンダー」
としてまとめた静的Webサイトです。ビルド不要・フレームワーク不要（Vanilla HTML/CSS/JS）
なので、そのまま GitHub Pages で公開できます。

## ファイル構成

```
koyomi/
├── index.html          … ページ本体・メタタグ・構造化データ・暦の解説記事/FAQ/サイトについて（静的コンテンツ）
├── css/style.css        … 「紙・綴じ穴・ミシン目」を模した日めくりデザイン + 解説記事セクションのスタイル
├── js/
│   ├── astro.js          … 太陽黄経・新月時刻の天文計算（低精度近似式）
│   ├── lunar.js           … 旧暦・二十四節気・六曜・月齢・日干支・一粒万倍日/天赦日の算出
│   ├── moonNames.js        … 月齢に対応する和名（十六夜・満月など）と英訳
│   ├── i18n.js              … 日本語/英語の文言辞書
│   ├── illustrations.js     … 季節のアイコン風イラスト・月齢アイコン・イラストの説明文
│   ├── historyEvents.js      … 今日は何の日（日本語版はwikitext直接パース／英語版はREST API）
│   ├── holidays.js            … 日本の祝日情報（holidays-jp APIを利用）
│   └── app.js                  … 画面描画・ナビゲーション・ページめくりアニメーション
├── robots.txt
└── sitemap.xml
```

## 表示がおかしいときのトラブルシューティング

「イラストが出ない」「日めくりカレンダー風の見た目にならない」という場合、
ほとんどのケースは **`css/style.css` や `js/` 以下のファイルが正しく読み込めていない**
ことが原因です。以下を確認してください。

1. ブラウザで公開後のページを開き、右クリック→「検証」→ Network タブを見て、
   `style.css` や `astro.js` などが `200`（成功）で読み込まれているか確認する。
   `404` になっている場合は、GitHub リポジトリに `css/` `js/` フォルダが
   **中身ごと**アップロードされているか確認してください（GitHubの「Add file →
   Upload files」でフォルダごとドラッグ&ドロップすると、ブラウザによっては
   中身が正しく展開されないことがあります。可能であれば `git push` での
   アップロードをおすすめします）。
2. ファイル名・フォルダ名の大文字小文字が完全に一致しているか確認する
   （GitHub Pages は Linux 上で動作するため大文字小文字を区別します）。
3. ブラウザのキャッシュが古いままの場合があるので、スーパーリロード
   （Windows: Ctrl+Shift+R / Mac: Cmd+Shift+R）を試す。
4. Console タブに赤いエラーが出ていないか確認する（`app.js` は各表示処理を
   独立して実行するようにしているため、一部の機能が失敗しても他の部分の
   表示が完全に消えることはない設計になっていますが、根本原因の特定には
   Console のエラーメッセージが役立ちます）。

## ローカルで確認する

ブラウザの `fetch` を使うため `file://` では一部機能（今日は何の日）が動きません。
下記のように簡易サーバーを立てて確認してください。

```bash
cd koyomi
python3 -m http.server 8000
# http://localhost:8000 を開く
```

## GitHub Pages への公開

1. このフォルダの中身をリポジトリのルート（またはお好きなブランチ）に置く
2. リポジトリの Settings → Pages で公開ブランチ/フォルダを指定
3. `index.html` 内の `https://example.com/` (canonical, og:url, sitemap.xml) を
   実際に公開するURLに書き換える

**AdSense の ads.txt を使う場合の注意**：GitHub Pages のプロジェクトページ
（`username.github.io/リポジトリ名/` の形式）は URL のパスが1階層深くなるため、
`ads.txt` をドメイン直下に置けず認証に失敗することがあります。independent な
カスタムドメインを設定するか、ユーザー/組織ルートページ（`username.github.io`
そのもの）にこのサイトを置くと解決しやすいです。

## 機能の仕組みと注意点

- **旧暦・二十四節気・月齢**：Jean Meeus の低精度天文公式（太陽黄経・新月時刻）を
  JavaScript で実装し、算出しています。国立天文台の公式暦とは天文暦モデルの
  精度差により、まれに1日程度ずれる可能性があります（特に閏月が入る年の
  月境界付近）。実運用で完全一致が必要な場合は、国立天文台の「暦要項」データ
  を別途組み込むことをおすすめします。月齢アイコンは新月からの経過日数を
  もとに、満ち欠けの形をSVGで直接描画しています。また「十六夜」「立待月」
  「有明の月」など日本古来の月の呼び名（と英訳）を、最も近い呼び名を選ぶ形で
  表示しています（`js/moonNames.js`）。
- **イラスト**：以前は複数の要素を組み合わせた「情景」でしたが、小さく表示すると
  分かりにくかったため、主役のモチーフを1つだけ大きく太い線で描く「アイコン」
  スタイルに変更しました。月ごとに4種類（およそ1週間ごと）のバリエーションを
  用意しています（`js/illustrations.js`）。
- **一粒万倍日・天赦日**：日本の伝統的な「選日」（吉日）を表示しています。
  どちらも二十四節気のうち「節」（立春・啓蟄・清明など12個）で区切られる
  「節月」と、その日の「日干支」（十干十二支）の組み合わせで決まります。
  日干支は国立天文台 暦計算室が公表している公式（干支番号 = (JDN+49) mod 60）
  で算出し、一粒万倍日は12の節月それぞれに割り当てられた2つの日支、天赦日は
  立春・立夏・立秋・立冬を境とする4つの季節それぞれに割り当てられた単一の
  日干支と照合しています。2026年の該当日数・具体的な日付を複数の暦サイトの
  公表データと突き合わせて検証済みです（`js/lunar.js`）。
- **ページめくりアニメーション**：前後の日に移動すると、実物の日めくりを
  破り取るような回転＋フェードアウトのアニメーションで前のページが消え、
  新しいページがふわっと落ち着くように現れます（`prefers-reduced-motion`
  設定を尊重し、アニメーションを抑えたい場合は無効化されます）。
- **六曜**：旧暦の月・日から算出する伝統的な計算式を使用しています。
- **今日は何の日**：
  - 英語版は Wikipedia の公開REST API
    (`https://en.wikipedia.org/api/rest_v1/feed/onthisday/all/{mm}/{dd}`) を
    認証なし・クライアントサイドで呼び出しています。
  - 日本語版は、このREST APIが日本語版ウィキペディアを正式にサポートして
    おらず空振りすることがあったため、`ja.wikipedia.org` の「M月D日」ページ
    本文(wikitext)を MediaWiki Action API (`origin=*` でCORS許可) から直接
    取得し、「== できごと ==」「== 誕生日 ==」の節をその場でパースする方式に
    変更しました。万一この方法も失敗した場合は、最終手段として英語版の
    データを注記付きで表示します（`js/historyEvents.js` 参照）。
  - Wikipediaのページ構成が将来変更された場合、パース処理の調整が必要に
    なる可能性があります。
- **日本の祝日**：`holidays-jp.github.io` の静的JSON API
  (`https://holidays-jp.github.io/api/v1/date.json`) から取得しています。
  GitHub Pages上の静的ファイルなので認証・CORSの問題がなく安定しています。
  取得結果は24時間 localStorage にキャッシュされます。対応期間は去年・今年・
  来年分（API側の仕様）のため、それ以外の年に移動した場合は祝日の赤色表示は
  適用されません（日曜日の赤色表示・土曜日の青色表示は全期間で有効です）。
- **生まれてから何日目**：入力した誕生日はこの端末のブラウザ（localStorage）
  にのみ保存され、外部には送信されません。

## SEO 対応

- タイトル・meta description・Open Graph タグを日付ごとに動的更新
- `WebSite` / `WebPage` の構造化データ（JSON-LD）を出力
- **`FAQPage` 構造化データ**を追加（下記の「暦の基礎知識・FAQ」セクションの
  内容に対応）。検索結果でFAQのリッチリザルト（Q&A形式の展開表示）が
  表示される可能性があります。
- URLハッシュ（例: `#/2026-07-11/ja`）で日付・言語を状態化 → その日をブックマーク/共有可能
- `robots.txt` / `sitemap.xml` を同梱
- meta keywords に一粒万倍日・天赦日・月齢・十六夜・日本の祝日などを追加

※ 日々更新される暦情報（旧暦・六曜など）はクライアントサイドJSで描画される
SPA構成のため、検索エンジンがJavaScriptを実行しない場合は読み取れない
可能性があります。一方で、下記の「暦の基礎知識・FAQ」記事部分は**静的HTML
としてページのソースに直接書かれている**ため、JavaScriptの実行有無に
関わらず検索エンジン・クローラーに読み取られます。より確実なSEOを狙う
場合は、日付ごとに静的HTMLを事前生成する仕組み（プリレンダリング）の
追加を検討してください。

## Google AdSense 対策（パブリッシャーコンテンツ不足への対応）

日めくりカレンダーのようなツール系サイトは、AdSenseの審査で「パブリッシャー
の価値あるコンテンツが少ない」という指摘を受けることがあります（入力待ちの
フォームや、ページ内の主要な情報がJSでしか表示されない場合など）。これに
対応するため、以下を追加しています。

- **「暦の基礎知識」記事セクション**（`#koyomiGuide`）：旧暦・六曜・
  二十四節気・月齢・一粒万倍日/天赦日・日本の祝日について、それぞれ
  数百字程度で解説する読み物を追加しました。日本語・英語の両方を用意し、
  `<html lang="ja|en">` の切り替えに連動して表示が切り替わります
  （CSSの属性セレクタ `html[lang="ja"] [data-lang="en"] { display:none; }`
  等で制御。JS実行前のデフォルトは日本語表示）。
- **FAQセクション**（`#faqBlock`）：5つの質問と回答を静的HTMLで用意し、
  `FAQPage` 構造化データも付与しています。
- **「このサイトについて」セクション**（`#aboutPrivacy`）：サイトの説明、
  広告配信事業者（Google AdSense等）がCookieを使用する場合がある旨の
  開示、Googleの広告ポリシーページへのリンクを含む簡易プライバシー
  ポリシーを掲載しています。AdSenseの審査・ポリシー上、広告を掲載する
  サイトにはこうした開示が求められることが多いため、実際に広告を導入する
  際は内容を実情に合わせて見直してください。

**AdSense の ads.txt を使う場合の注意**（既出）：GitHub Pages のプロジェクト
ページ（`username.github.io/リポジトリ名/` の形式）は URL のパスが1階層
深くなるため、`ads.txt` をドメイン直下に置けず認証に失敗することがあります。
独自のカスタムドメインを設定するか、ユーザー/組織ルートページ
（`username.github.io` そのもの）にこのサイトを置くと解決しやすいです。

**注意**：これらの対応はAdSense審査通過を保証するものではありません。
最終的な判断はGoogle側の審査によります。また、実際に広告を配置する際は
Google AdSenseの管理画面から発行される広告コード（`<script>`タグ等）を
`index.html` に追加する必要があります（本バージョンには広告コード自体は
含まれていません）。

## カスタマイズのヒント

- 配色・季節ごとのアクセントカラーは `css/style.css` の `:root` 変数と
  `.season-*` クラスで管理しています。
- フォントは Google Fonts の Shippori Mincho / Zen Kaku Gothic New を使用。
  差し替える場合は `index.html` の `<link>` と CSS の `--font-*` 変数を変更してください。
